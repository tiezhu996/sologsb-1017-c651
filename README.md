# 场记台 · 电影剧本连续性检查工具

使用 React、Vite、TypeScript 和 MUI 从零实现的电影剧本连续性工作台。项目围绕场景、角色、道具、服装、时间线与修订颜色建立真实数据关系，并在场景变化后自动给出可审阅的连续性警告。

## 功能

- 大纲视图、场景详情、资料库与响应式工作区。
- 维护场景、角色、道具、服装、故事时间、拍摄时段、修订颜色和锁定状态。
- 自动检查角色无铺垫出现、道具未提前建立、服装与时间冲突、时间线倒退。
- 审阅人逐条接受或忽略警告，作者可回复并保留修改理由。
- 全文搜索场景名、摘要、地点、故事时间和修改理由。
- 保存不可变版本快照，将历史版本与当前工作稿逐字段比较或恢复。
- **两套状态所有权**：剧本工作稿掌握正文（场名、摘要、内外景、地点、页数等）与修订色；现场交接包只记拍摄日、出场角色、道具、服装更换和现场备注，合并不会覆盖作者内容。
- **按场次编号 + 修订色归位导入**：编号缺失、修订色不一致或编号指向已拆分场次时，本地内容原样保留，记录进入“待裁决区”，由作者/场记采纳归位或拒绝。
- **发布事务**：发布前留存上一包与检查点；断网失败可回滚或重试，重试按 `包 + 条目`幂等覆盖，不重复追加。
- **锁定门禁**：存在未裁决记录时，任何场次都不能锁定。
- 撤销重做、自动本地保存和常用键盘操作。
- Service Worker 运行时缓存，已访问的生产页面可离线打开。

## 技术栈

- React 18
- Vite 6
- TypeScript
- MUI 6 + Emotion

## 本地开发

```bash
npm install
npm run dev
```

Vite 开发服务器默认使用本地端口 `5174`，该端口不代表容器映射。生产容器仅监听 `80`。

## 生产构建

```bash
npm install
npm run build
npm run preview
```

构建结果位于 `dist/`。

## Docker

```bash
docker build -t sologsb-1017 .
docker run --rm -p 10017:80 sologsb-1017
```

Dockerfile 使用多阶段构建，最终由 nginx 在容器 `80` 端口提供静态文件。宿主端口由根编排文件维护，源码中没有硬编码宿主端口。

## 数据说明

剧本、审查决定、回复和版本快照均保存在浏览器 `localStorage`。应用不调用网络接口，清空站点数据会同时清空本地剧本。

## 剧本稿与现场交接包的所有权

为避免“剧本正文和现场事实混在一稿里、断网拍完合并覆盖作者内容”，应用把状态拆成两套：

| 归属 | 内容 |
| --- | --- |
| 本地剧本工作稿 | 场名、摘要、内外景、地点、日夜、故事时间、页数、**修订色**、修改理由、正文关系 |
| 现场交接包 | 拍摄日、出场角色、道具、服装更换、现场备注；包内只带编号与修订色快照用于归位 |

工作流：

1. 拍摄前在“现场交接”页从当前工作稿**建包**（正文不进包），导出 JSON 带到现场，断网编辑后再导入。
2. 导入时按**场次编号 + 修订色**归位：命中即标记可发布；修订色不一致、编号不存在、同编号对应多场（已拆分）或角色/道具/服装引用无法落实时，**本地内容保留**，条目进“待裁决区”，可手动选择归位场次或拒绝。
3. 发布会先写**检查点**（包快照与受影响场次的旧现场记录）。“模拟断网发布”可复现失败：上一包与检查点保留，现场记录不变；重试按包+条目幂等覆盖，绝不重复追加；也可一键按检查点回滚。
4. 只要存在 `pending` 裁决记录，场景详情里的“锁定场次”会被拒绝；全部裁决清零后才能锁定。
