# 场记台 · 电影剧本连续性检查工具

使用 React、Vite、TypeScript 和 MUI 从零实现的电影剧本连续性工作台。项目围绕场景、角色、道具、服装、时间线与修订颜色建立真实数据关系，并在场景变化后自动给出可审阅的连续性警告。

## 功能

- 大纲视图、场景详情、资料库与响应式工作区。
- 维护场景、角色、道具、服装、故事时间、拍摄时段、修订颜色和锁定状态。
- 自动检查角色无铺垫出现、道具未提前建立、服装与时间冲突、时间线倒退。
- 审阅人逐条接受或忽略警告，作者可回复并保留修改理由。
- 全文搜索场景名、摘要、地点、故事时间和修改理由。
- 保存不可变版本快照，将历史版本与当前工作稿逐字段比较或恢复。
- 撤销重做、自动本地保存和常用键盘操作。
- Service Worker 运行时缓存，已访问的生产页面可离线打开。

## 剧本工作稿与现场交接包（两套所有权）

剧本正文与现场拍摄事实分开持有，互不覆盖：

- **本地剧本工作稿（作者侧）**：掌握正文、场次信息与**修订色**，保存在浏览器本地。
- **现场交接包（现场侧）**：只记录拍摄日、出场角色、道具、服装更换和备注，可在断网时维护草稿，不包含任何剧本正文。
- **发布**：组包时冻结草稿为不可变快照；模拟链路失败会保留上一包并写入检查点，重试沿用同一 `requestHash`，服务端按哈希幂等去重，重复发送不会重复追加。可用“模拟链路失败”开关复现该流程。
- **导入归位**：按“场次编号 + 修订色”匹配本地场次自动挂入；编号查无、修订色不一致（保留本地色）或编号指向已拆分场次时，不改正文，记录进入**待裁决区**，由人手动挂到具体场次或标记不采用。重复导入同一条目会被跳过。
- **锁定闸门**：存在未裁决记录时，任何场次都不能锁定；裁决全部处理后才允许锁定。
- 场景详情页的“现场交接记录”面板只读展示已归位的拍摄事实。

## 技术栈

- React 18
- Vite 6
- TypeScript
- MUI 6 + Emotion

## 本地开发

```bash
npm install
npm run dev
```

Vite 开发服务器默认使用本地端口 `5174`，该端口不代表容器映射。生产容器仅监听 `80`。

## 生产构建

```bash
npm install
npm run build
npm run preview
```

构建结果位于 `dist/`。

## Docker

```bash
docker build -t sologsb-1017 .
docker run --rm -p 10017:80 sologsb-1017
```

Dockerfile 使用多阶段构建，最终由 nginx 在容器 `80` 端口提供静态文件。宿主端口由根编排文件维护，源码中没有硬编码宿主端口。

## 数据说明

剧本、审查决定、回复、版本快照和现场交接包（草稿、已发布包、检查点、发布日志、归位记录、待裁决记录）均保存在浏览器 `localStorage`。模拟发布的服务端“收件箱”同样存于 `localStorage`，用于演示幂等去重。应用不调用真实网络接口，清空站点数据会同时清空本地剧本与交接数据。
